## 1. Core Physics & Simulation Principles

The AEGISSTOR Digital Twin evaluates counterfactual interventions against an immutable Hard Safety Envelope in an isolated in-memory execution sandbox.

### Mathematical & Physical Axioms:
1. **Zero Real-World Mutation**: The simulation sandbox strictly manipulates cloned state vectors. Physical storage volume writes, block migrations, or disk partitions are never mutated (`SHADOW_MODE_ENABLED: true`).
2. **Deterministic Reproducibility**: Given an identical device metadata dictionary, base forecast contract, intervention parameters, and random seed $S$, the simulation produces bitwise-identical trajectories:
   $$\mathcal{S}'(t) = f(\mathcal{S}(t), a, \theta, S)$$
3. **Operational Lead Time Invariant**:
   An action candidate $a$ is executable if and only if its estimated execution duration $T_{\text{action}}$ is strictly less than the predicted reserve breach horizon $T_{\text{breach}}$:
   $$T_{\text{action}} < T_{\text{breach}}$$
   If $T_{\text{action}} \ge T_{\text{breach}}$, the action is rejected with `INFEASIBLE_LEAD_TIME`.

## 2. Supported Scenarios & Physical Models

### Scenario 1: `DO_NOTHING` (Baseline Projection)
- **Model**: Projects the baseline $q_{50}$ capacity trajectory without mitigation.
- **Physical Assumption**: Organic user traffic and background write workloads persist at diurnal historical rates.

### Scenario 2: `EXPAND_CAPACITY` (Online LUN Expansion)
- **Model**: Extends pool capacity by $\Delta C$ after a provisioning lead time $T_{\text{lead}}$:
  $$C_{\text{total}}'(t) = \begin{cases} C_{\text{total}}, & t < T_{\text{lead}} \\ C_{\text{total}} + \Delta C, & t \ge T_{\text{lead}} \end{cases}$$
- **Physical Assumption**: Requires unpartitioned raw physical blocks in the storage chassis. Minor metadata re-striping induces $+2.0\%$ controller CPU overhead.

### Scenario 3: `TIER_COLD_DATA` (Cold Object Migration)
- **Model**: Evacuates volume $V_{\text{cold}}$ at migration bandwidth $B_{\text{mig}}$ (MB/s).
  $$\text{Duration} = \frac{V_{\text{cold}}}{B_{\text{mig}}}$$
- **I/O Bus Contention & Latency Penalty**:
  Streaming blocks to secondary tiers saturates controller channels, inflating tail latency non-linearly:
  $$\Delta \text{Latency}(\%) = \left(\frac{B_{\text{mig}}}{300.0}\right)^{1.35} \times 22.0\%$$
- **Hard SLA Violation**: If projected latency exceeds $L_{\text{max}}$ (e.g. 20ms for NVMe), the intervention is disqualified with `VIOLATES_LATENCY_SLA`.

### Scenario 4: `RESCHEDULE_TASK` (Off-Peak Maintenance)
- **Model**: Moves heavy RAID scrubbing and backup windows to 02:00 - 05:00 UTC off-peak hours.
- **Physical Assumption**: Does not alter total stored bytes, but relieves peak daytime queue depth and reduces tail latency by $-18.0\%$.

### Scenario 5: `WORKLOAD_REBALANCING` (Inter-Pool Tenant Migration)
- **Model**: Re-routes a percentage $\rho$ of concurrent IOPS to an adjacent storage pool.
- **Physical Assumption**: Requires that destination storage pool has $\ge 30\%$ free IOPS headroom.

### Scenario 6: `CUSTOM_SCENARIO` (Authorized Parameter Overrides)
- **Model**: Allows authorized administrators to evaluate custom capacity deltas ($\Delta C \in [-50\text{ TB}, +100\text{ TB}]$), durations, and contention penalties within validated ranges.

## 3. Capacity-Latency Coupling Physics

Flash controllers experience internal garbage collection (GC) and wear-leveling write amplification when available reserve drops below 20%:
$$\text{Penalty}_{\text{lat}}(\text{ms}) = \max\left(0.0, \frac{\text{Util} - 80.0\%}{20.0\%} \times 6.5\text{ ms}\right)$$
This non-linear degradation couples capacity shortages with application latency failures.

## 4. Known Limitations & Scientific Honesty

1. **Simulated Estimates vs Measured Evidence**:
   Outputs generated by the Digital Twin represent physics approximations, not guaranteed real-world execution. All UI panels explicitly display:
   `SIMULATED ESTIMATE — NO PHYSICAL MUTATION`.
2. **Fabric Bandwidth Homogeneity**:
   Simulations assume stable SAN/NVMe-oF network bandwidth without intermediate switch port packet drops.
3. **No Automatic Destructive Execution**:
   Human approval in the Intervention Studio merely records an administrative dry-run decision into the audit log. Physical mutations must be applied via separate, site-specific infrastructure-as-code automation.
